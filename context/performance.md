# 재현 가능한 성능 측정

실행:

```powershell
cargo run --release --locked -p whostty-core --example terminal_bench
```

출력은 JSON 한 줄이다. 코드가 바뀐 뒤 같은 장비·같은 release 설정으로 비교한다.
이 측정은 VT 엔진과 셀 복사를 대상으로 한다. GPU 프레임 시간, 화면에 나타날 때까지의 입력 지연,
셸/WSL 오버헤드, 프로세스 RSS, Ghostty와의 비교는 포함하지 않는다.

## 2026-10-17 macOS 기준값

- 장비: Apple M3 Pro, macOS 26.5.2, aarch64, Rust 1.88.0.
- release 빌드, 120열 × 40행. 검색/복사 테스트에는 기록 9,961줄과 현재 화면을 사용했다.
- 최초 실행 후 연속 3회 측정했다. 일반 데스크톱 환경이라 CPU 부하와 클럭을 격리하지 않았다.
- 아래 처리량은 ANSI 스타일을 포함한 입력 바이트 기준이다. ASCII와 Unicode의 작업 내용이 달라 서로의 우열을 뜻하지 않는다.

| 항목 | 중앙값 | 3회 범위 |
|---|---:|---:|
| ASCII VT 파싱 | 164.31 MiB/s | 112.22–166.36 MiB/s |
| Unicode VT 파싱 | 149.01 MiB/s | 109.18–154.98 MiB/s |
| 약 1만 줄에서 없는 문자열 검색 | 7.492 ms | 7.374–7.605 ms |
| 4,800개 셀 복사 | 14.466 μs | 14.384–14.706 μs |

검색 수치는 각 실행에서 30회 평균, 셀 복사는 각 실행에서 1,000회 평균을 구한 뒤 비교했다.
렌더러는 셀 버퍼를 재사용하며, 스냅샷을 만든 다음 그리드 잠금을 풀고 글자 배치·GPU 도형을 만든다.
위 복사 수치는 잠금·레이아웃·GPU 제출을 모두 포함한 프레임 비용으로 해석하지 않는다.

위 초기 기준값은 Alacritty 검색 엔진을 UI 스레드에서 호출하던 구현의 결과다.
후속 구현은 취소 가능한 백그라운드 검색으로 바꾸고, 16행씩 그리드를 복사한 뒤 잠금 밖에서 검색한다.
아래 Mac 기준값과 별도로 Windows 실기기의 입력 경로는 [2026-10-20 검증 기록](windows-validation-2026-10-20.md)에 있다.

## 백그라운드 검색 도입 후 추가 측정

같은 장비·그리드에서 release 예제를 연속 3회 실행했다. 일반 데스크톱 환경이며 부하는 격리하지 않았다.
검색 구현이 바뀌어 결합 문자 좌표 매핑과 행 복사 비용을 포함한다. 단순한 속도 향상 수치로 비교하지 않는다.

| 항목 | 중앙값 | 3회 범위 |
|---|---:|---:|
| 동기 검색 API, 1만 줄 no-match 평균 | 8.423 ms | 8.134–8.454 ms |
| 백그라운드 검색 요청 함수 반환 | 64.042 μs | 60.750–67.791 μs |
| 백그라운드 검색 전체 시간 | 8.629 ms | 8.617–9.216 ms |
| 동시 그리드 잠금 probe의 실행별 최대 대기 | 18.417 μs | 11.917–93.208 μs |

검색 전체 시간은 100ms 입력 debounce를 제외하고 작업 생성·스케줄링·poll을 포함한다.
잠금 probe는 실행마다 64–66회이며 시스템의 최악 대기 시간을 보장하는 값은 아니다.
GPU나 실제 GUI 입력 지연을 측정한 값으로 해석하지 않는다.

## Shaped text CPU 제출 기준값

```powershell
cargo test --release --locked --package whostty shaping::tests::render_submission_benchmark -- --ignored --nocapture
```

동일 Mac/M3 Pro/Rust 1.88.0에서 연속 3회 실행했다. 기본 시스템 글꼴, 17pt, 1배율, 80열×40행 ASCII run을 그린다.
초기 1회, warmup 10회, 측정 200프레임이며 각 실행의 p50/p95를 구했다. UI frame과 glyph mesh 생성·egui tessellation 비용이다.
초기 수치는 지연 폰트 준비·CPU atlas 생성도 포함하며 configure_fonts의 파일 읽기는 그 전에 수행한다.
PTY 파싱·grid snapshot·배경/장식·앱 chrome·GPU 업로드/제출·VSync·실제 입력 지연은 포함하지 않는다. 일반 데스크톱 부하는 격리하지 않았다.

| 항목 | 3회 중앙값 | 3회 범위 |
|---|---:|---:|
| 첫 CPU frame | 8.674 ms | 8.607–15.946 ms |
| warm CPU p50 | 0.176 ms | 0.175–0.202 ms |
| warm CPU p95 | 0.181 ms | 0.180–0.235 ms |

측정 후 cache는 glyph 35개와 layout 40개였다. GPU 프레임 시간이나 Ghostty 대비 수치로 해석하지 않는다.
벤치마크는 기본 테스트에서 ignore되며 명시한 release 명령으로 실행한다. 시간 임계값으로 CI를 실패시키지 않는다.
